# TortoiseBotManager-QuestControl

Vanilla World of Warcraft 1.12.1 addon for tracking quest pickup, hand-in issues and linked reward choices by grouped TortoiseBotsManager bot.

## Quest Control window

Click **Quest** directly left of TBM's **Info** header button, or type `/tbmq`, to toggle the compact window. It has full class-coloured bot names, Blizzard `!`/`?` icons beside quest titles, bundled green tick/red X/neutral question mark per bot (hover for meaning), direct per-bot item reward icons (inline, without a redundant reward-status icon, with wrapping only when needed) and contextual small Talk, Accept and bin controls. No persistent stage/status prose appears in the main matrix. Use the larger high-contrast bottom-right grip to resize, drag the title header or scroll in either direction; window position and manual size persist per character. Click the gear in the title bar to access five independent options: **Filter Owned Bot Messages**, **Filter Other Bot Messages**, **Hide bot names**, **Hide bot quest progress messages**, and **Fade when inactive (20%)**. Hiding names keeps each bot's class icon; hover that icon to see the full name. Columns and auto-sized windows shrink/re-expand to fit the icon-based layout while retaining room for relevant reward/action icons, and separately sized layouts persist. All five options default OFF for new installations and preserve explicitly saved choices. When idle fade is enabled, an empty or fully resolved window is 20% opaque while not hovered; moving the pointer anywhere inside the frame or the open settings menu temporarily restores full opacity. An unresolved quest also keeps the window fully opaque. The existing per-row 7+3-second fade still applies independently. Escape leaves the window open; close via X, TBM Quest or /tbmq. The compact UI uses native game elements with optional pfUI backdrop.

Accepting a quest creates a pickup checkpoint for each currently grouped TBM bot. An explicit linked bot acceptance confirms pickup, even if the bot message arrives before your action. Otherwise the bot shows **Not confirmed**, not a claimed failure. Use the **gossip Talk icon** to ask the bot to interact with your nearby selected quest giver, then the **clipboard Accept icon** to send the original linked quest when QuestControl has captured that link. A greyed-out Accept icon means no trustworthy quest link is available. Neither action fabricates a success response; verify the bot's subsequent chat.

Ordinary quest hand-ins are assumed successful without requiring every bot to chat confirmation. An **explicit** bot `I have completed the quest [questlink]` message now creates a temporary green-tick hand-in confirmation even when the original silent row has cleared; other bots stay neutral, and the existing 7+3 second fade applies. Explicit hand-in problems and reward-choice requests create actionable entries; a linked reward prompt is recorded even before the player's hand-in. Each reward choice uses the individual bot's original item link: hover for the item tooltip or click to whisper `r [original itemlink]`. A reply acknowledges the selected reward. Rows clear when the tracked bots have resolved their relevant checkpoint; the **bin icon** manually dismisses a row.

Pending state and original links are saved per character across reloads and relogs. The two account-wide chat visibility settings are **Filter Owned Bot Messages** (TBM roster/claimed bots, migrated from the previous checkbox) and **Filter Other Bot Messages** (senders outside the TBM roster). **Both filters default OFF for new installs in `0.1.7-dev`; existing saved choices, including the explicit legacy-owned setting, are preserved.** **Only messages successfully recognised as quest notification templates are hidden** on party/raid/whisper channels; unrelated chat remains visible. Other-sender recognition is a template match, not independently verified bot identity. Filtering never changes owned-bot quest processing, rows or original reward messages. Independently, the **Hide bot quest progress messages** option hides objective counts such as `Bristleback Trapper: 3/10` (including the server's coloured form) and quest-linked item count updates from **all senders**, regardless of TBM owned/claimed roster membership, on party/raid/raid-leader/whisper channels. It does not require either existing filter. Outsider bot identity cannot be authenticated from chat alone, so a human deliberately sending an identical objective-count format may also be hidden when enabled. Stock Vanilla 1.12 cannot reliably identify quest-giver game objects or construct a missing original quest link.

The bundled bin, clipboard-check and small status-symbol TGA assets are local rendered icon glyphs for reliable Vanilla/Turtle display; the first two are not byte-identical upstream pfQuest_Group files (binary transfer was unavailable). Verify their appearance in game. The UI and quests require in-game retesting. See `DEV_PROGRESS.md` for known limitations and test steps.
